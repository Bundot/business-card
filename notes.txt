Step 1 · HTML5 DocType & Boilerplate
index.html

HTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Digital Business Card</title>
  <link rel="stylesheet" href="style.css" />
</head>
What?

We are declaring standard HTML5 document metadata, configuring responsive mobile scaling, and linking our external stylesheet.

Where?

In index.html, right at the top inside the <head> tag before any visible elements.

How?

By setting <!DOCTYPE html> for modern standards mode, the viewport meta tag for device width parity, and a <link rel="stylesheet"> element pointing to style.css.

Why?

Without the DOCTYPE declaration, the browser defaults to Quirks Mode, and without the viewport meta tag, mobile screens will emulate a desktop viewport and scale the card down unreadably.

Step 2 · Card Container & Profile Header
index.html

HTML
<body>
  <div class="card">
    <div class="avatar">JD</div>
    <h1 class="name">Jane Doe</h1>
    <p class="title">Product Designer</p>
    <p class="bio">Crafting clean, accessible, and user-centric digital experiences.</p>
What?

We are setting up the main card shell and personal branding hierarchy: avatar initials badge, owner name, job role, and professional summary.

Where?

At the top of the <body> inside a centered .card wrapper container.

How?

By nesting an initials badge container, a semantic <h1> for the primary entity name, and <p> elements with specific class names (.title, .bio) for targeted styling.

Why?

Using semantic headings ensures assistive technologies read the cardholder's name as the primary title of the document, establishing an immediate visual and accessibility hierarchy.

Step 3 · Contact Details List & Document Close
index.html

HTML
    <ul class="contact-list">
      <li class="contact-item">
        <span class="label">Email</span>
        <a href="mailto:jane.doe@example.com">jane.doe@example.com</a>
      </li>
      <li class="contact-item">
        <span class="label">Phone</span>
        <a href="tel:+1234567890">+1 (555) 019-2834</a>
      </li>
      <li class="contact-item">
        <span class="label">Web</span>
        <a href="https://janedoe.design" target="_blank" rel="noopener">janedoe.design</a>
      </li>
    </ul>
  </div>
</body>
</html>
What?

We are constructing an accessible, structured contact list for communication channels and closing out the HTML document.

Where?

Directly below the .bio paragraph, completing the inner contents of .card before closing </body> and </html>.

How?

By using an unordered list (<ul>) populated with labeled list items (<li>) containing actionable URI protocols (mailto:, tel:, and external web URL with target="_blank" and rel="noopener").

Why?

Semantic list elements allow screen readers to inform users of the exact item count, while active URI protocols (mailto:, tel:) launch native mail and phone clients on user click.

Step 4 · CSS Design Tokens, Global Reset & Viewport Centering
style.css

CSS
:root {
  --bg-page: #f1f5f9;
  --bg-card: #ffffff;
  --text-primary: #0f172a;
  --text-secondary: #64748b;
  --text-muted: #94a3b8;
  --accent: #2563eb;
  --border-color: #e2e8f0;
  --border-subtle: #f1f5f9;
}

* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

body {
  min-height: 100vh;
  display: flex;
  justify-content: center;
  align-items: center;
  background-color: var(--bg-page);
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
  padding: 1.5rem;
}
What?

We are establishing CSS color variables, normalizing element dimensions with a universal box reset, and centering the entire layout in the viewport.

Where?

At the very top of style.css inside :root, *, and body rules.

How?

Using display: flex, justify-content: center, and align-items: center alongside min-height: 100vh to anchor the card dead-center on all displays.

Why?

CSS variables maintain color consistency across the codebase, while flexbox viewport centering prevents the card from clinging awkwardly to the top-left corner on wide desktop screens.

A constrained card container with defensive padding and subtle drop shadows provides real-world tactile depth, preventing text from stretching excessively on desktop displays.

What?

We are styling the clean, divider-separated contact rows, setting a fixed-width label column, and configuring hover states for links.

Where?

At the end of style.css, finalizing all visual styling rules.

How?

By applying display: flex to each list item with a fixed width: 70px on .label, stripping default bullets with list-style: none, and adding a smooth color transition on a:hover.

Why?

Fixed-width metadata labels create a straight visual vertical alignment for contact values, ensuring high scanability without resorting to complex grid or table markup.
